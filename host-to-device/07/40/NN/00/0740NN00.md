# `07 40 NN 00` - Set the input mode of keys

Sets how `NN` keys report their presses: `NN` pairs of [key index](../../../../../formats/cape/key-index.md) and mode follow from byte 4, up to 30 per packet (`07 40 1e`), the last packet carrying the rest. It gets no reply.

| Mode | Seen as |
|---|---|
| `c0` | HID and Corsair events |
| `c1` | the same, for the brightness button of the K95 RGB Platinum |
| `80` | HID events only |

## K95 RGB Platinum

- When iCUE puts the keyboard in software mode it writes `c0` for 120 keys and `c1` for the brightness button (`47`): `07 40 1e` four times and `07 40 01`, the 121 keys of the keyboard. It writes the table again at every change of profile in its interface. When it closes it sends only [`07 04 01`](../../../04/070401.md) and leaves the table as it is.
- **A table that sets the G keys and the profile button to `80` (HID only), followed by [`07 05 02 00 03 00`](../../../05/070502.md), leaves the K95 RGB Platinum without its hardware macros and without its profile button in hardware mode**, until the keyboard is power cycled (re-plugging the cable; a USB re-enumeration is not enough) or iCUE takes it over and gives it back. To give the keyboard back to hardware mode, [`07 04 01`](../../../04/070401.md) alone is enough; a `c0` table left in place does no harm.
