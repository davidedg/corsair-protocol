# `07 17 0e` - End a change of a slot (K95 RGB Platinum)

Part of the on-board profile file system of the K95 RGB Platinum ([devices/k95p.md](../../../../devices/k95p.md)). iCUE sends it twice in the write of a slot: after clearing the slot entry with [`07 15 SS 00`](../../15/SS/00/0715SS00.md), which empties the slot, and after the last file. Byte 4 has always been 0; it may be a parameter (iCUE has an enumeration CommitFlag: None 0, Red 1, Green 2, Blue 4, All 7) *(inferred)*.

Clearing the slot entry and sending `07 17 0e` is also how a slot is deleted:

```
> 07 15 SS 00 <20 zero bytes>
> 0e 17 0d 00          < status 0
> 07 17 0e
```

After it the slot table ([`0e 17 04`](../../../0e/17/04/0e1704.md)) shows the slot as 20 zero bytes, its size ([`0e 17 03 00`](../../../0e/17/03/00/0e170300.md)) is 0, and its files are gone. `07 17 0e` does not make the firmware reload the bindings of the active slot.
